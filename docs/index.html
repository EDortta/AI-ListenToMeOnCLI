Two complementary tools
Policy pack meets runtime enforcement
📋

AI-Agents

The policy pack — the "what and why" of governance. A reusable starter kit that brings structure, contracts, and discipline to every AI agent working in your codebase.

Ships with a universal AGENTS.md contract, role-specific agent contracts (programmer, reviewer, security, privacy), issue templates, session-close workflows, and a handoff log — everything an AI agent needs to operate predictably.

github.com/EDortta/AI-Agents →
⚙️

AI-GovernanceKit

The runtime CLI — the "how" of enforcement. Validates, automates, and integrates your governance policy into daily development and CI pipelines.

Provides a doctor command that validates the AI-Agents file structure, session automation hooks, and CI integration points — so governance violations are caught before they reach review.

Core capabilities
Everything agents need to behave.

From a one-line install to enterprise-grade boundaries — built for real teams, real projects.

📜

Universal Contract

AGENTS.md is the single source of truth for every AI agent in your repo — precedence rules, hard limits, execution loop, and quality gates in one file.

🎭

Role-Based Contracts

Separate contracts for programmer, reviewer, security, issue automation, and privacy compliance — agents load only what they need.

🛡️

Hard Scope Limits

docs/limits.md defines what agents may never do — prohibited actions, security boundaries, and branch/approval gates that override any other instruction.

🔁

Resumable Sessions

Every session closes with an updated handoff.md and RESUME.md so any agent — or human — can pick up exactly where the last session ended.

📁

Structured Issue Workflow

Epic-based issue folders, ready-to-use templates (task, privacy checklist, retrospective), and a work-ID convention that links planning docs to commits.

🔒

Security by Default

Every delivery requires a security-impact classification. Agents must document affected surfaces, abuse paths, mitigations, and residual risk before marking work done.

⬆️

Safe Upgrade Path

The --upgrade flag updates kit-owned files while preserving all project-specific context: overviews, limits, handoffs, issues, and credentials.

🩺

GovernanceKit Doctor

Run governancekit doctor to validate the entire AI-Agents structure in seconds — ideal as a pre-commit hook or CI gate.

🧠

Personal Touch

Agents adapt communication style (tone, depth, language) when ~/.config/USER.md is present — governance behavior stays unchanged, delivery becomes personal.

How it works
Up and running in minutes.

Four steps from zero to governed.

Install the kit

Run the one-liner installer. It copies all contracts and templates into your project directory.

Fill two files

Describe your product in docs/software-overview.md and set hard boundaries in docs/limits.md. Mark both as ready.

Validate with doctor

Run governancekit doctor to confirm the structure is complete. Agents will refuse to start if it isn't.

Start your first issue

Use the task template under docs/issues/templates/. Agents follow the execution loop automatically from here.

bash <(curl -fsSL https://raw.githubusercontent.com/EDortta/AI-Agents/v1.0.2/scripts/install-agents-kit.sh) \ --target /path/to/your-project --upgrade
Personal Touch
Governance that knows you.

Drop a ~/.config/USER.md in your home config directory. Agents read your profile at session start and adapt communication style — tone, depth, language, and decision framing — to match how you think. Governance rules and quality gates are completely unchanged.

  • Global — one file serves all your projects
  • Optional — kit works perfectly without it
  • Never committed to any repository
  • Generate it from ConhecerTe or write it manually
# ~/.config/USER.md (example) ## Communication Style - Direct, technical, low-ceremony - Skip pleasantries; get to the tradeoffs - Prefer bullet points over paragraphs - Assume senior-level context ## Decision Framing - Lead with risks, then options - Flag irreversible actions explicitly - One recommendation, not a menu ## Language - English for code and docs - Portuguese for casual discussion
